# Telegram ↔ Software Factory

Мост принимает задачи из личного чата Telegram, распознаёт голосовые сообщения через Groq и передаёт задачи в разговор **Software Factory Bot** (`bot-f94ac52a7fe2499692bb62b0dc0b5b07`). Когда бот выполнит задачу, его рабочая сессия отправит ответ или файл (например, APK) в тот же чат через `tg_send.py`. Ожидайте от моста «✅ Передал задачу» после приёма вебхуком; это не означает, что сама задача уже выполнена.

## Подготовка

1. В Telegram откройте [@BotFather](https://t.me/BotFather), выполните `/newbot` и сохраните токен как `TELEGRAM_BOT_TOKEN`. Откройте личный чат с новым ботом и нажмите **Start**.
2. Создайте ключ на [Groq Console](https://console.groq.com/keys) и сохраните как `GROQ_API_KEY`. Голосовые, аудио и видеосообщения-кружки транскрибируются моделью `whisper-large-v3` с автоопределением языка.
3. Настройте автоматизацию Devin с триггером `webhook:incoming`, которая проверяет `X-Webhook-Secret`. Запишите URL и секрет триггера как `DEVIN_WEBHOOK_URL` и `DEVIN_WEBHOOK_SECRET`. Настройте доставку сообщения **в разговор Software Factory Bot с указанным выше ID**, а не в отдельную сессию разработчика.
4. Укажите свой числовой ID в `TELEGRAM_OWNER_ID`. Если ID неизвестен, временно используйте `9007199254740991` (значение вне диапазона ID Telegram), запустите мост и отправьте `/id` в чат бота. Он покажет ваш ID, не пересылая сообщение в Devin. Замените временное значение своим ID и перезапустите мост. Можно указать несколько ID через запятую.

Храните токен и ключи в секретах окружения или в локальном `.env`, не отправляйте их в чат и не коммитьте. Секрет вебхука должен совпадать на обеих сторонах; для внешнего адреса используйте HTTPS.

## Настройка маршрута в Devin

Мост отправляет JSON с полями `source="telegram"`, `kind="text"|"voice"`, `chat_id`, `message_id`, `from` и `text`. Для документов и фото добавляется `attachments` с `file_id` и `file_name`. Это ссылки по ID внутри Telegram, а не копии файлов. Для голосового сообщения `text` содержит подпись (если она есть), затем транскрипт. Сам транскрипт также показывается в чате.

В автоматизации задайте фиксированного получателя — **Software Factory Bot** (`bot-f94ac52a7fe2499692bb62b0dc0b5b07`) — и передайте ему текст задачи, вложения (если есть) и числовые `chat_id` и `message_id`. Не выбирайте получателя из входящего JSON. Попросите бота передавать `chat_id` рабочей сессии и отправлять туда итоговый ответ и запрошенные файлы командой ниже. Дайте рабочим сессиям доступ к этому репозиторию и к секрету `TELEGRAM_BOT_TOKEN` **того же** Telegram-бота. Для исходящих сообщений другие ключи не нужны.

## Запуск

Локально или на VPS с Python 3.12:

```sh
cp .env.example .env
# Заполните .env
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python bridge.py
```

Либо через Docker (с заполненным `.env`):

```sh
docker build -t telegram-bridge .
docker run -d --name telegram-bridge --restart unless-stopped --env-file .env telegram-bridge
docker logs -f telegram-bridge
```

Для VPS оставьте контейнер запущенным либо настройте менеджер процессов для `python bridge.py`. Мост сам забирает сообщения через long polling: входящий порт открывать не нужно. Запускайте только один экземпляр на токен.

## Ответы и APK

Из рабочей сессии Software Factory Bot, используя `chat_id` именно этой задачи:

```sh
python tg_send.py --chat 123456789 --text "Готово, изменения проверены."
python tg_send.py --chat 123456789 --file ./app-release.apk --caption "Готовый APK"
```

Если опустить `--chat`, требуется `TELEGRAM_OWNER_ID`: берётся первый ID из списка. Длинный текст отправляется частями. APK приходит как документ; лимит загрузки через облачный Telegram Bot API — 50 МБ. Для большего файла можно отправить ссылку вместо документа.
